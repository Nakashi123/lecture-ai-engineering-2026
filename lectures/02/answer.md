# 第2回 解答

## 演習

- **使用モデル・設定：** `Qwen/Qwen3.5-0.8B`（revision `2fc06364715b967f1860aea9cf38778875588b17`）、LoRA（量子化なし）、`lora_r=16`、`lora_alpha=32`、`lr=2e-4`、`seed=42`、`do_sample=False`。元の条件は20エポックで40ステップ。
- **自分で学習を実行したか：** はい（`executed_training_myself=True`）。Google ColabのTesla T4で、20エポックと10エポックの両方を実行。**一括実行版ノートブックを使用し、同一Colabセッション内で20エポックの学習済みモデル・trainerを解放してから基盤モデルを新たに読み込み、10エポックを学習した。ランタイム全体の再起動は行っていない。**
- **学習前（両条件共通）：** `format_rate = 2/21 = 9.5%`、`content_rate = 0/21 = 0%`。
- **学習後（20エポック）：** `format_rate = 21/21 = 100%`、`content_rate = 19/21 = 90.5%`。
- **学習後（10エポック）：** `format_rate = 21/21 = 100%`、`content_rate = 17/21 = 81.0%`。
- **退行した質問：** 配布ノートブックの定義（学習前に形式と内容の両方が正しく、学習後に誤答になった質問）では、どちらも0問。ただし学習前の両方正解が0問だったため、退行がないことだけで性能維持を保証するものではない。
- **学習後に残った失敗と型：**
  - 20エポック：2問。FAQにない「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」に対して、別のFAQ項目を当てはめて`needs_review: false`と断定した。
  - 10エポック：4問。「PDF以外でも出せますか」はFAQにPDF指定があるのに`needs_review: true`とした。「成績はいつ出ますか」「課題の文字数に制限はありますか」「参考文献の書き方に指定はありますか」は`needs_review: true`ではあるが、回答文に必須語句「確認」がなく、配布コードの内容判定では不正解だった。
- **知識を問う質問（セクション6）：** 20エポックの学習後、FAQにない3問のうち「担当教員の名前」「次回の講義テーマ」の2問には確認を求めたが、「最終課題の締切」はFAQにある**通常の課題の提出期限**を流用して断定した。10エポックでも同じ傾向。対照質問の「課題の提出期限」はFAQ内の項目として正しく回答した。
  - **出力データ上の注意：** セクション6の`FAQ にある`フラグは`q in gold`で作っているため、対照質問も`false`と表示される。実際のFAQ本文に通常の課題提出期限は記載されており、対照質問をFAQ外と解釈しない。
- **学習で変わったこと・変わらなかったこと：** どちらの学習条件でもJSON形式は全21問で守れるようになった。しかし、FAQに書かれていない事実について、別項目の情報を流用して断定する誤りは残った。今回の架空FAQの日付等は、実際の講座の提出期限を示すものではない。

## 宿題

- **取り組んだレベル：** 基礎。
- **変えた設定：** `CONFIG["num_train_epochs"]` だけを **20 → 10** に変更。モデルとrevision、データ（train 14件、valid 7件、test 21問）、`lr=2e-4`、`lora_r=16`、`lora_alpha=32`、`seed=42`、`warmup_steps=6`、`do_sample=False`等は共通。学習済みモデルを解放し、新規に基盤モデルを読み込んで2回目を実行した。**資料の「セッションを再起動」の指定を厳密に満たす手順ではない**ことを明記する。

### 結果

| 評価指標 | 20エポック | 10エポック |
| --- | ---: | ---: |
| 学習前 `format_rate` | 9.5%（2/21） | 9.5%（2/21） |
| 学習後 `format_rate` | **100%（21/21）** | **100%（21/21）** |
| 学習前 `content_rate` | 0%（0/21） | 0%（0/21） |
| 学習後 `content_rate` | **90.5%（19/21）** | **81.0%（17/21）** |
| 最終ログ loss | **0.0139**（40ステップ時） | **0.0973**（20ステップ時） |
| 学習時間（秒） | **236.3秒** | **115.1秒** |
| 学習ステップ数 | 40 | 20 |

※最終ログlossは`trainer.state.log_history`に記録された最後の学習loss。全ステップの平均loss（20エポック0.4193、10エポック0.8288）とは別。学習時間は`train_runtime`で、評価に要した時間は含まない。

### 考察・限界

10エポックに減らしても形式遵守率は100%に達した一方、内容正解率は90.5%から81.0%に下がった。学習時間は約半分になった。形式を揃えるためのFine-Tuningは有用だと考えられるが、未知の質問を適切に判断する能力までは保証されない。回答内容を正しく保つには、回答の根拠確認やRAGなど別の対策も必要だと思う。最新情報を知識として参照する用途では、Fine-Tuningより検索・RAGを先に検討する。

今回は各条件1回、同じColabセッション内でのモデル再読み込みによる比較であり、ばらつきや独立セッションでの再現性は未検証。エポック数の変更に伴ってcosine学習率スケジュールの総ステップ数も変わるため、精度差をエポック数単独の因果効果と断定できない。また、`content_rate`はFAQとの全面的な意味的一致ではなく、`needs_review`の一致と指定語句の包含で判定する指標である。
